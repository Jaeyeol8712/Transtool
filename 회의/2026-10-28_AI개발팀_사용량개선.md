# AI 개발팀 보고 — Claude 사용량 줄이는 방법 (2026-10-28)

대표 지시: "지금 클로드 사용량 너무 빨라, 개선할 수 있는 방법 AI 연구자가 만들어"

## 무엇이 사용량을 먹고 있나 (우리 운영 기준, 큰 순서)
1. **아침 회의가 두 번 돈다** — 예전 작업(trig_01Rgj…)과 새 작업(trig_011vp…)이 둘 다 08:35. 회의 1회 = 17팀 웹 검색 17~34번 + 회의록 + 컨펌판·jack 쓰기 (Opus). 10-27에는 이 회의가 한도에 걸려 실패.
2. **이 대화방이 너무 길다** — 일간 보고·카페 원고 전달 예약 작업이 이 대화방을 깨워서 실행됨. 깨울 때마다 긴 대화 전체를 다시 읽어 비용이 큼. (Anthropic 도움말: 긴 대화일수록 사용량이 커짐, 주제가 바뀌면 새 대화 권장)
3. **전문성 강화 17팀 매일** — 매일 웹 검색 17~34회. 도움말: 검색·리서치는 사용량을 더 씀.
4. **모든 작업이 Opus** — 도움말: 모델 선택이 한도 소진 속도에 영향.
5. 보조 에이전트(병렬 작업) 사용 — 하나 띄울 때마다 처음부터 다시 읽음.

## 개선안 (예상 효과 큰 순서)
| # | 개선 | 효과 | 필요한 것 |
|---|---|---|---|
| 1 | 예전 아침 회의 작업 일시정지 (회의 하루 1번) | 매일 회의 1회분 절약 (가장 큼) | 대표 OK (권한 확인 필요) |
| 2 | 카페 원고는 고정창(카페 원고판)에 미리 다 올려 두고, 매일 이 대화방을 깨우는 카페 원고 전달 작업 6개(4~9일차)는 일시정지 | 긴 대화 깨우기 6회 절약 | 대표 OK |
| 3 | 일간 버튼 클릭 보고서를 이 대화방이 아닌 새 짧은 작업으로(또는 GitHub가 직접 메일 발송) | 매일 긴 대화 깨우기 1회 절약 | 대표 OK |
| 4 | 전문성 강화 순번제: 하루 4팀씩 돌아가며(약 4~5일에 한 바퀴), 팀당 검색 1회 | 검색 17~34회 → 4회 | 컨펌 |
| 5 | 아침 회의 보고 길이 줄이기(표 1개 + 4줄 결론 + 할 일), jack·컨펌판 쓰기는 한 번에 묶어서 | 출력·쓰기 감소 | 컨펌 |
| 6 | 정해진 반복 작업(카페 전달·보고서)은 Sonnet 모델로, 판단 많은 회의만 Opus | 반복 작업 비용 감소 | 컨펌 |
| 7 | 대표님 쪽: 새 주제는 새 대화에서, 지시는 한 메시지에 모아서, 설정 > 사용량에서 확인 | 대화 길이 감소 | 대표 습관 |
