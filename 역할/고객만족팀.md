## 1. 누구인가

## 2. 전문 지식 체계 (10년차가 아는 것)

### 2-1. 접수 채널 설계
- **단일 창구** → 창구가 여러 개면 누락이 생긴다. 소규모 사이트는 이메일 하나를 공식 창구로 정하고, 문의 페이지·푸터·계산기 하단 안내가 모두 같은 주소를 가리키게 한다. 기준: 사이트에 공개된 연락 주소는 하나, 처리방침의 권리행사 연락처도 같은 주소.
- **정적 사이트의 한계** → GitHub Pages는 서버가 없어 문의 폼을 직접 받을 수 없다. 선택지는 ① `mailto:` 링크(제목·본문 미리 채움) ② 외부 폼 서비스 ③ Supabase 등 DB. 외부 폼·DB는 개인정보 처리 위탁·보관 문제가 생기므로 처리방침 개정이 함께 필요하다(법무팀). 기준: 지금은 `mailto:` + 유형별 제목 머리말.
- **유형별 제목 머리말** → `mailto:` 링크에 `subject=[오류 제보]` 처럼 머리말을 미리 넣으면, 받는 쪽 필터가 자동으로 라벨을 붙인다. 이용자가 고치더라도 대부분 그대로 보낸다(실무 경험칙). 본문에 "페이지 주소 / 무엇이 잘못됐는지 / 근거" 틀을 넣으면 재질문이 줄어든다.
- **Gmail 기능** → 필터는 조건(보낸 사람·제목·포함 단어)에 맞는 새 메일에 라벨 붙이기·보관·별표·전달 등을 자동 적용한다. 전달 필터는 새 메일에만 적용된다 [5]. 템플릿은 설정 > 고급 > 템플릿 '사용'으로 켜고, 작성 창의 '더보기'에서 저장·삽입한다. 템플릿 이름은 바꿀 수 없어 지우고 새로 만든다 [6].
  - Gmail의 `+` 별칭(예: `aroundtool2026+error@gmail.com`)으로 유형별 주소를 만드는 방법도 있으나, 일부 이용자 메일 프로그램·사이트가 `+` 를 거부할 수 있다. 공식 도움말 원문 확인 필요. 기준: 주소는 하나, 구분은 제목 머리말로.
- **도메인 메일(contact@aroundtool.com)** → 자기 도메인 주소는 신뢰를 주지만, 받으려면 MX 레코드와 메일 서버(또는 Cloudflare Email Routing 같은 전달 서비스)가 필요하다. Cloudflare 전달은 도메인 DNS를 Cloudflare에서 관리해야 쓸 수 있다고 알려져 있다(공식 문서 열람 실패, 확인 필요).

### 2-5. 개인정보 권리 요청과 법정 기한 (개인정보보호법)
- **열람(법 제35조, 시행령 제41조)** → 정보주체는 처리 항목·내용, 수집·이용 목적, 보유 기간, 제3자 제공 현황 등 중 원하는 사항을 골라 열람을 요구할 수 있다. 처리자는 **요구를 받은 날부터 10일 이내** 열람하게 하거나 일부만 열람하게 하고, 열람통지서로 알린다. 일부 열람이면 사유와 이의제기 방법을 함께 알린다. 즉시 열람시키면 통지서를 생략할 수 있다 [1].
  - 절차: 열람 요구 방법은 **수집 절차보다 어렵지 않게**, 서면·전화·전자우편·인터넷 등 쉬운 수단으로, 원칙적으로 수집한 창구로도 요구할 수 있어야 하고, **홈페이지가 있으면 절차를 홈페이지에 공개**한다 [1].
  - 정당한 사유가 있으면 알리고 연기할 수 있다(법 제35조 제3항 후단, 원문 확인 필요) [4].
- **정정·삭제(법 제36조, 시행령 제43조)** → 열람한 개인정보에 대해 정정·삭제를 요구할 수 있다. 처리자는 지체 없이 조사해 조치하고, **요구를 받은 날부터 10일 이내** 조치 사실, 또는 따르지 않은 사실·이유·이의제기 방법을 통지서로 알린다. 삭제는 복구·재생이 안 되게 한다. 다른 법령이 수집 대상으로 정한 정보는 삭제를 거절할 수 있다 [2].
- **처리정지(법 제37조, 시행령 제44조)** → 요구를 받은 날부터 **10일 이내** 결과(정지 사실, 또는 따르지 않는 사실·이유·이의제기 방법)를 고시된 결과 통지서로 알린다 [3].
- **본인·대리인 확인** → 요구자가 본인 또는 정당한 대리인인지 합리적 방법으로 확인한다. **수집할 때 요구하지 않던 증빙을 추가로 요구하면 안 된다**(예: 이메일로만 받았는데 신분증 사본을 요구) [4].
  - 우리에게 의미: 우리는 이메일 주소·문의 내용만 받는다. 본인 확인은 "같은 이메일 주소에서 온 요청인지"로 충분한 경우가 많다. 신분증 사본을 받지 않는다.
- **동의 철회** → 지체 없이 파기 등 조치 [4].
- **수수료** → 실비 범위에서 청구할 수 있으나, 우리는 받지 않는다 [4].
- **기록** → 요구와 처리 결과를 기록하고 정기적으로 점검한다 [4]. 기록에는 이메일 주소를 남기지 않고 접수 번호·접수일·종류·완료일만 남긴다(결정기록: 개인정보를 저장소에 남기지 않는다).
- **결함 사례** → 10일을 넘겨 회신, 가입은 온라인인데 탈퇴만 신분증·방문 요구 [4].

### 2-6. 정보통신망법: 권리 침해 정보와 임시조치
- **삭제·임시조치(제44조의2)** → 사생활 침해·명예훼손 등 권리를 침해받은 사람이 침해 사실을 소명해 삭제나 반박 내용 게재를 요청하면, 정보통신서비스 제공자는 지체 없이 삭제·임시조치 등을 하고 요청인과 게재자에게 알린다. 판단이 어렵거나 다툼이 예상되면 접근을 임시로 막는 임시조치를 할 수 있고, **임시조치 기간은 30일 이내**다. 게재자는 재게시를 청구할 수 있다 [7][8].
  - 필요한 조치의 내용과 절차는 **약관에 미리 구체적으로** 밝혀야 한다(제44조의2 제5항, 법무팀·커뮤니티 관리자 [2] 재인용) [8].
- **임의 임시조치(제44조의3)** → 제공자가 스스로 권리 침해를 인정하면 요청이 없어도 가릴 수 있다 [7].
- **2026 개정(법률 제21305호, 2026-01-06 공포, 2026-07-07 시행)** → 허위조작정보 개념 도입, 고의 유통으로 손해를 입히면 최대 5배 징벌적 손해배상, 확정된 불법·허위조작정보 반복 유통에 10억 원 이하 과징금. 주 대상은 정보 게재를 업으로 하는 자이며 대상 기준(구독자·조회수)은 시행령에서 논의 중으로 확정 여부 확인 필요 [7].
- **우리에게 의미** → 게시판이 열리기 전에는 사이트 글 대부분을 우리가 직접 썼다. 이때는 임시조치가 아니라 **우리 글의 정정 요청**으로 다루고 법무팀 판단으로 문장·이미지 단위로 고친다. 게시판이 열리면 이용자 글은 커뮤니티 관리자의 임시조치 절차를 따른다.

### 2-7. 스팸·피싱 처리
- **공개 주소는 스팸을 부른다** → 페이지에 공개한 이메일 주소는 수집 로봇에 걸린다. 주소를 그림·자바스크립트로 감추는 방법은 효과가 일부 있지만 이용자 불편(복사 불가, 화면 읽기 프로그램)이 생긴다(효과 연구는 오래된 자료가 대부분, 확인 필요). 기준: 주소는 글자로 공개하고 Gmail 스팸 필터와 우리 필터로 거른다.
- **처리 원칙**
  - 스팸에는 답장하지 않는다(살아 있는 주소임을 알려 준다). Gmail '스팸 신고'만.
  - 첨부파일·단축 링크가 있는 "계정 정지·저작권 위반·결제 실패" 메일은 열지 않는다. 진짜 권리 침해 주장은 대상 URL과 권리 근거가 본문에 있다. 의심되면 링크를 누르지 않고 사이트 쪽 URL만 확인한다.
  - 스팸함을 하루 1회 훑어 정상 문의가 잘못 들어갔는지 확인한다(특히 업소 운영자의 첫 메일).
- **우리가 보내는 메일** → 회신 메일에 추천 글·제휴 링크를 넣으면 영리 목적 광고성 정보가 될 수 있다(정보통신망법 제50조, 법무팀 2-7). 기준: 회신에는 문의와 관련된 사이트 페이지 링크만.

### 2-8. 답장 템플릿 원칙
- 구조: 인사 1줄 → 받은 내용 요약 1줄 → 우리가 한 일/할 일과 날짜 → 필요한 자료(있으면) → 마무리 1줄 → 서명("어라운드툴 고객만족팀").
- 금지: 책임 인정·부인 단정(법무팀 확인 전), 날짜 없는 "빠른 시일 내", 제휴 링크, 감정적 표현, 다른 이용자 정보.
- 이름: 고객이 쓴 이름이 있을 때만 "○○님". 없으면 "안녕하세요".
- 템플릿 목록은 '3. 적용'의 템플릿 묶음 참고. Gmail 템플릿으로 저장한다 [6].

### 2-9. VOC를 개선으로 연결
- **태그와 집계** → 문의마다 유형 코드와 대상 페이지를 남긴다. 주 1회 유형별 건수, 페이지별 건수, 반복 문의 상위 3개를 보고.

   - T2 추가 자료 요청: "정확히 확인하려면 [페이지 주소/입력값/근거 링크]가 필요합니다. 회신 주시면 이어서 처리하겠습니다."
   - T3 처리 완료(오류·정정): "알려 주신 내용을 확인해 [날짜]에 [페이지]를 고쳤습니다. 바뀐 부분: [한 줄]. 제보해 주셔서 감사합니다."
   - T4 반영하지 않음: "확인한 결과 [근거: 공식 고시·자료]에 따라 현재 내용을 유지합니다. 다른 자료가 있으면 알려 주세요."
   - T5 권리 침해 1차 조치: "신고하신 [이미지/문장]을 [날짜 시각]에 내렸습니다. 사실 확인 후 [예상일]까지 최종 결과를 알려 드리겠습니다." (법무팀 확인 후 발송)
   - T6 개인정보 요청 결과: "[날짜]에 받은 [열람/정정/삭제/처리정지] 요청을 [조치 내용]로 처리했습니다. (따르지 못한 경우: 이유 … / 이의가 있으면 이 메일로 회신하시거나 개인정보침해 신고센터(118)에 문의하실 수 있습니다.)" — 법정 통지 항목: 조치 사실 또는 거절 사실·이유·이의제기 방법 [2][3]. 신고센터 안내 문구는 법무팀 확인 필요.
   - T7 광고·협찬 문의: "어라운드툴은 업소·브랜드의 협찬, 유료 수록·유료 리뷰를 받지 않습니다. [그 밖의 제안은 검토 후 영업일 5일 안에 답을 드립니다.]"
5. **VOC 주간 보고 시작** (매주 수요일 주간 보고에 맞춰)
   - 유형별 건수, 반복 문의 상위 3개, 새 계산기·지역 요청 목록, 반영된 개선과 그 페이지의 방문 변화(데이터 분석가).

### 하지 말아야 할 것
- 공개 연락 주소를 여러 개 두는 것(문의 누락).
- 문의자 이메일·이름·본문을 저장소·회의록·컨펌판에 옮기는 것(결정기록, `team-ops` 는 공개 저장소).
- 개인정보 요청에 신분증 사본을 요구하는 것, 10일을 넘기는 것 [1][2][4].
- 권리 침해 신고를 받고 페이지 전체를 내리는 것(이미지·문장 단위로 조치, 검색 유입 보호 — 법무팀 기준).
- 법무팀 확인 없이 책임을 인정·부인하는 회신, 내용증명·수사기관 요청에 직접 답하는 것.
- 회신 메일에 제휴 링크·추천 글 홍보를 넣는 것.
- 스팸에 답장하거나 의심 링크를 누르는 것.
- 대량 회신·자동 회신 발송을 대표 확인 없이 켜는 것(결정기록).
- 처리 기간을 지킬 수 없는 날짜로 약속하는 것.

## 4. 매일 쓰는 점검표
1. 새 문의 수(유형별)와 아직 담당 팀에 넘기지 않은 문의가 있는가? (`문의/1-새로옴` 0건 목표)
2. 첫 회신이 영업일 1일을 넘긴 문의가 있는가?
3. 개인정보 요청(P1)의 법정 마감(10일)까지 3일 이내로 남은 건이 있는가? [1][2][3]
4. 권리 침해(R1·R2)·법적 통지(L1)가 새로 왔는가? 24시간 1차 조치·대표 보고를 했는가?
5. 담당 팀에 넘긴 건 중 회신 대기(`문의/3-회신대기`)가 7일을 넘긴 것이 있는가? 넘기면 아침 회의에서 담당 팀에 확인.
6. 스팸함에 정상 문의가 잘못 들어가 있지 않은가?
7. 같은 내용 문의가 4주 안에 3회 이상 쌓인 것이 있는가? 있으면 컨펌판 안건.
8. (주 1회) `contact.html` 의 주소·처리 기간 문구가 실제 운영과 같은가? 처리방침 연락처와 같은가?
9. 개인정보위·방미통위·법제처 새 소식 중 권리행사 절차·임시조치 관련 변경이 있는가? 있으면 '6. 최신 동향'.
